

## 三、Gate 判据（两层拆分）

```text
Gate A1 · PROFESSIONAL SOFTWARE COMPATIBILITY
  问题：目标专业软件与卦眼（同一输入）是否给出同一月建？
  方法：用上表「边界 -1min / 边界 / 边界 +1min」三点做人工对照；
        立春另有秒级三点。
  状态：WAITING FOR USER MANUAL INPUT

Gate A2 · SOLAR TERM ABSOLUTE PRECISION
  状态：PARTIALLY VERIFIED
  Verified second-level case:
    2026 LiChun = 04:02:08 +08:00
  2026 LiChun precision gap:
    FIXED
  Other 2026 solar terms:
    minute-level only
    no fabricated second-level truth
```

> 不得写成 `ALL 2026 SOLAR TERMS SECOND-LEVEL VERIFIED` —— 那是假的。
> 本轮的修复范围只有**已核实的 2026 立春单点**。

### 立春精度修复（R3-B-DATA-PRECISION-FIX）

```text
根因：分钟级官方显示值被保存为 :00 秒 Instant，
      而该分钟内存在可验证的真实秒级交节时刻。
      分钟级数据**不足以表达**该秒级边界 —— 不是 HKO 错了。

修复前：2026-02-03T20:02:00Z → 04:02:00 起即切寅月（提前 8 秒）
修复后：2026-02-03T20:02:08Z → 04:02:08 起才切寅月
数据包：schemaVersion 2 / revision 2 / precision = second /
        sourceOverride = 中国科学院紫金山天文台科普部
```

### 自建天文尺子的现状（不可作为真值）

```text
状态：REJECTED AS GATE ORACLE（保留为 diagnostic tool）
证据：与官方发布时刻相比，时间残差最大约 729 秒（立夏）；
      2026 立春对秒级公开值残差约 -343 秒。
根因（已定位）：视黄经**日变率正确**（1.0187 vs 官方 1.0187 °/日），
      但在官方交节瞬间，本尺子给出的视黄经已越过目标角 9～30 角秒，
      且该偏差随季节变化（与中心差 C 同相）—— 属绝对项偏差，
      自洽性（求根反代 = 0.000000°）不能证明绝对正确。

旧的 <0.01° 自检已降级为 coarse sanity check：
      0.01° ≈ 14.6 分钟时间，通过它**不足以**证明分钟级或秒级精度。
```
